# Feature 0052: Centralized System Prompts with Legal Counsel Personality

## Overview
Implement a centralized prompt configuration system to refine the AI assistant's tone of voice. The assistant will act as a legal counsel for private real estate property owners, understanding query context (owner vs renter perspective), prioritizing document-based answers, expressing uncertainty when information is not in documents, and avoiding hallucination.

## Target Audience
Private real estate property owners managing their contract portfolios. System acts as legal counsel in their favor.

## Core Requirements
1. **Context-aware responses**: Understand query motive (user asking as owner vs renter)
2. **No hallucination**: Base answers on RAG information; if not in documents, must express uncertainty
3. **Document-first priority**: Answer from documents first; clearly express when info not in documents
4. **General knowledge usage**: Only for opinions, legal approaches, and best practices when explicitly asked
5. **Source citations**: Call out sources when relevant
6. **Confidence expression**: System must be very sure information is not in documents before saying so

## Implementation Algorithm

### Step 1: Create Prompt Configuration Module
1. Create `backend/domain/chat/prompts.py`
2. Define `SystemPrompts` class with constants
3. Implement `get_system_prompt()` method:
   - Input: `context_type: str` ("document_query" | "general_query" | "no_info_found")
   - Input: `language_instruction: str`
   - Output: Complete system prompt string
   - Logic: Combine base personality + context-specific instructions + language instruction

4. Implement `get_streaming_prompt()` method (same signature as above)

### Step 2: Detect Document Context
In `rag_engine.py`:
1. In `_create_llm_func()`: Add `has_document_context` to kwargs
2. In `_create_streaming_llm_func()`: Add `has_document_context` to kwargs
3. In `query()` method (line 446): Detect document context from `document_ids` parameter
4. In `query_stream()` method (line 594): Detect document context from `document_ids` parameter
5. Pass `has_document_context` flag through to LLM function calls

### Step 3: Integrate Prompts into RAG Engine
1. Import `SystemPrompts` at top of `rag_engine.py`
2. Replace 3 hardcoded system prompt strings with `SystemPrompts` calls
3. Pass context type based on:
   - `has_document_context=True` → "document_query"
   - `has_document_context=False` → "general_query"
4. Maintain existing language instruction appending logic
5. Preserve all existing functionality (message building, history, kwargs filtering)

### Step 4: Update UI Loading Indicators
1. In `ChatContext.tsx`: Track whether current query has document context
2. Pass `hasDocumentContext` flag to `Message` component
3. In `Message.tsx`: Conditionally render loading text based on flag

## Prompt Content Guidelines

### Base Personality
- Act as legal counsel for private real estate property owners
- Professional, trustworthy, detail-oriented
- Prioritize client's interests (property owner perspective)
- Understand dual context: sometimes owner, sometimes renter

### Document Query Context
- "I will analyze your documents to provide accurate information"
- "All my answers are based on the documents you've provided"
- "I will cite specific sources when relevant"
- "If information is not in your documents, I will clearly state this"

### No Document Info Context
- "I thoroughly searched your documents but could not find this information"
- "This information is not available in your uploaded documents"
- "Would you like my general legal perspective on this matter?"

### General Knowledge Context
- "Based on general legal practices and best approaches..."
- "From a legal counsel perspective, I recommend..."
- Clear distinction: "This is general advice, not based on your specific documents"
