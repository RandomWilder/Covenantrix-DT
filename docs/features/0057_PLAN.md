# Feature 0057: Document Summarization System

## Overview
Implement hierarchical map-reduce summarization for legal documents with progress tracking, caching, and translation support. Users click a "Summarize" button on individual document cards in the Documents tab to generate comprehensive, structure-preserving summaries (1-2 pages). Summaries are cached and can be translated to user's preferred language on demand.

## Core Algorithm: Hierarchical Map-Reduce

### Processing Strategy
1. **Batch Layer**: Split document chunks into batches of 15 chunks each
2. **Batch Summaries**: Generate focused summary for each batch (preserves legal context)
3. **Section Summaries**: If >3 batches, merge batch summaries into section summaries
4. **Final Summary**: Merge all summaries with structure detection and formatting
5. **Length Control**: Target 1 page (≈800 words), max 2 pages (≈1600 words)

### Structure Detection During Summarization
- Auto-detect numbered sections (e.g., "1.", "1.1", "Article I")
- Identify clause patterns (e.g., "WHEREAS", "NOW THEREFORE")
- Recognize addendums/appendices
- Preserve hierarchical relationships in final summary
- Maintain legal section numbering in output

**Batch Processing Algorithm**:
1. Get all chunks for document from RAG storage
2. Split into batches of 15 chunks
3. For each batch:
   - Create context from 15 chunks
   - Generate batch summary (LLM call with legal summarization prompt)
   - Emit progress: `batch_processing` stage
4. If ≤3 batches: proceed to final merge
5. If >3 batches: create section summaries first
   - Group batches into sections (3-4 batches per section)
   - Generate section summary from batch summaries
   - Emit progress: `section_merging` stage
6. Final merge:
   - Combine all summaries
   - Apply structure detection
   - Format with length control (1-2 pages)
   - Emit progress: `finalizing` stage

**Structure Detection Algorithm**:
1. Scan first 5 chunks for patterns
2. Identify section markers (numbers, "Article", "Section", etc.)
3. Extract hierarchy levels
4. Build structure map: {section_id: {title, level, position}}
5. Use structure map to organize final summary

**Translation Algorithm**:
1. Detect target language from user input using LLM
   - Prompt: "Identify the ISO 639-1 language code for: {user_input}"
   - Parse response to extract 2-letter code
2. Load original summary
3. Check if translation exists in cache
4. If not cached:
   - Generate translation with LLM
   - Preserve markdown formatting and structure
   - Cache translation
5. Return translated text

## Error Handling

### Backend Errors
- Document not found: 404 error
- Document not yet processed: 400 error with message
- LLM timeout: Retry with exponential backoff (max 3 attempts)
- Storage write failure: 500 error, cleanup partial data
- Translation detection failure: Default to English with warning

### Frontend Errors
- Network errors: Show retry button
- Stream interruption: Resume from last progress point
- Translation errors: Show error message, keep original summary

## Performance Considerations

### Backend (Verified in Testing)
- Process batches sequentially (avoid parallel LLM calls)
- **Actual performance tested**:
  - 15 chunks: ~169 seconds (2.8 minutes)
  - Estimated 3-5 seconds per batch for small documents
  - Larger documents (500 chunks): 3-5 minutes estimated
- Cache summaries aggressively (retrieval: ~2 seconds vs 169 seconds)
- Use streaming for progress feedback via SSE
- Translation: ~30-60 seconds depending on length

### Frontend
- Non-blocking UI during generation (use SSE stream)
- Progress persists across navigation using Zustand store
- Summary renders with markdown (Hebrew/English/other RTL support needed)
- Translation cached after first request (instant retrieval)
