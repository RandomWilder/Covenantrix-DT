# Knowledge Graph Visualization - Technical Plan

## Context
Implement an interactive knowledge graph visualization feature that displays entities and relationships extracted by LightRAG during document processing. Users will access this through a dedicated "Knowledge Graph" tab in the left sidebar navigation, providing visual insight into the semantic structure of their document collection.

## Phase 1: Backend API Layer (Graph Data Exposure)

### Goal
Create FastAPI endpoints to expose LightRAG's knowledge graph data (entities, relationships, and statistics) in a format optimized for frontend visualization.

### 1.1 Graph API Router
**File to create:** `backend/api/routers/graph_routes.py`

**Dependencies to import:**
```python
from fastapi import APIRouter, Depends, HTTPException, Query
from typing import Dict, List, Any, Optional
from infrastructure.ai.rag_engine import RAGEngine
from api.dependencies import get_rag_engine
import networkx as nx
```

**Endpoints to implement:**

1. **GET /api/graph/entities**
   - Query parameters: `limit` (Optional[int]), `entity_type` (Optional[str])
   - Returns: List of entities with id, label, type, description, source_id
   - Access: `rag_engine._rag.chunk_entity_relation_graph.get_all_nodes()` (NetworkXStorage wrapper)
   - Note: LightRAG uses NetworkXStorage wrapper, not direct NetworkX graph
   - Filter by entity_type if provided
   - Limit results if specified
   - Node data fields: `id`, `entity_name`, `entity_type`, `description`, `source_id`

2. **GET /api/graph/relationships**
   - Returns: List of relationships with source, target, weight, description, keywords
   - Access: `rag_engine._rag.chunk_entity_relation_graph.get_all_edges()` (NetworkXStorage wrapper)
   - Include edge metadata (weight, description, keywords)
   - **⚠️ CRITICAL:** Edge data fields in GraphML are `source`, `target` (NOT `source_id`, `target_id`)
   - **Implementation:** Use `edge_data.get('source', edge_data.get('source_id', ''))` for fallback
   - These fields contain the actual node IDs (entity names)

3. **GET /api/graph/graph**
   - Query parameter: `max_nodes` (int, default=500)
   - Returns: Complete graph structure with nodes and edges arrays
   - Response includes: nodes[], edges[], total_nodes, total_edges
   - Only include edges between nodes in the limited set
   - Performance optimization: Cap at max_nodes to prevent browser overload
   - Uses NetworkXStorage methods: `get_all_nodes()` and `get_all_edges()`

4. **GET /api/graph/stats**
   - Returns: Graph statistics for dashboard display
   - Calculate: total_nodes, total_edges, entity_type distribution, graph density
   - Density calculation: `density = total_edges / (total_nodes * (total_nodes - 1) / 2)`
   - Group entity counts by entity_type
   - Note: Manual density calculation (NetworkX not directly accessible)

**Error handling:**
- Handle case where RAG engine not initialized
- Return empty data structures if graph is empty
- Log warnings for missing graph data
- Handle NetworkXStorage wrapper properly (not direct NetworkX graph)

**⚠️ CRITICAL IMPLEMENTATION WARNING:**
```python
# ❌ WRONG - Will result in NO visible edges
source=str(edge_data.get('source_id', ''))
target=str(edge_data.get('target_id', ''))

# ✅ CORRECT - GraphML uses 'source' and 'target' attributes
source=str(edge_data.get('source', edge_data.get('source_id', '')))
target=str(edge_data.get('target', edge_data.get('target_id', '')))
```
Without this, edges won't connect to nodes because the field names don't match!

### 2.2 API Client Service
**File to create:** `covenantrix-desktop/src/services/api/GraphApi.ts`

**Implementation approach:** Class-based service extending `ApiService` (follows existing codebase pattern)

**Methods to implement:**
```typescript
import { ApiService } from './ApiService'
import type { 
  GraphData, 
  GraphStats, 
  EntityListResponse, 
  RelationshipListResponse 
} from '../../types/graph'

export class GraphApi extends ApiService {
  /**
   * Fetch complete graph structure
   * @param maxNodes - Maximum number of nodes to return (default: 500)
   */
  async getFullGraph(maxNodes: number = 500): Promise<GraphData> {
    try {
      const response = await this.get<GraphData>(`/api/graph/graph?max_nodes=${maxNodes}`)
      return response.data
    } catch (error) {
      console.error('Failed to fetch graph data:', error)
      throw new Error(`Failed to fetch graph data: ${(error as Error).message}`)
    }
  }

  /**
   * Fetch entities with optional filtering
   * @param limit - Maximum number of entities to return
   * @param entityType - Filter by specific entity type
   */
  async getEntities(
    limit?: number, 
    entityType?: string
  ): Promise<EntityListResponse> {
    try {
      const params = new URLSearchParams()
      if (limit !== undefined) params.append('limit', limit.toString())
      if (entityType) params.append('entity_type', entityType)
      
      const queryString = params.toString()
      const endpoint = queryString ? `/api/graph/entities?${queryString}` : '/api/graph/entities'
      
      const response = await this.get<EntityListResponse>(endpoint)
      return response.data
    } catch (error) {
      console.error('Failed to fetch entities:', error)
      throw new Error(`Failed to fetch entities: ${(error as Error).message}`)
    }
  }

  /**
   * Fetch all relationships
   */
  async getRelationships(): Promise<RelationshipListResponse> {
    try {
      const response = await this.get<RelationshipListResponse>('/api/graph/relationships')
      return response.data
    } catch (error) {
      console.error('Failed to fetch relationships:', error)
      throw new Error(`Failed to fetch relationships: ${(error as Error).message}`)
    }
  }

  /**
   * Fetch graph statistics
   */
  async getStats(): Promise<GraphStats> {
    try {
      const response = await this.get<GraphStats>('/api/graph/stats')
      return response.data
    } catch (error) {
      console.error('Failed to fetch graph statistics:', error)
      throw new Error(`Failed to fetch graph statistics: ${(error as Error).message}`)
    }
  }
}
```

3. **Force-Directed Layout Algorithm** ⚠️ CRITICAL:
   ```typescript
   /**
    * Apply force-directed layout to nodes
    * Creates natural clustering of connected entities
    */
   const applyForceLayout = (
     nodes: GraphNode[],
     edges: GraphEdge[]
   ): Map<string, { x: number; y: number }> => {
     // Build adjacency map
     const adjacency = new Map<string, Set<string>>();
     edges.forEach(edge => {
       if (!adjacency.has(edge.source)) adjacency.set(edge.source, new Set());
       if (!adjacency.has(edge.target)) adjacency.set(edge.target, new Set());
       adjacency.get(edge.source)!.add(edge.target);
       adjacency.get(edge.target)!.add(edge.source);
     });

     // Initialize random positions in wide area
     const positions = new Map<string, { x: number; y: number }>();
     nodes.forEach(node => {
       positions.set(node.id, {
         x: Math.random() * 2000,
         y: Math.random() * 1500
       });
     });

     // Force simulation parameters
     const iterations = 50;
     const repulsionStrength = 50000;
     const attractionStrength = 0.01;
     const coolingFactor = 0.95;

     // Run force simulation
     for (let iter = 0; iter < iterations; iter++) {
       const forces = new Map<string, { fx: number; fy: number }>();
       nodes.forEach(node => forces.set(node.id, { fx: 0, fy: 0 }));

       // Repulsive forces (all nodes push each other apart)
       for (let i = 0; i < nodes.length; i++) {
         for (let j = i + 1; j < nodes.length; j++) {
           const node1 = nodes[i];
           const node2 = nodes[j];
           const pos1 = positions.get(node1.id)!;
           const pos2 = positions.get(node2.id)!;

           const dx = pos1.x - pos2.x;
           const dy = pos1.y - pos2.y;
           const distSq = dx * dx + dy * dy + 0.01; // Avoid division by zero
           const dist = Math.sqrt(distSq);

           const force = repulsionStrength / distSq;
           const fx = (dx / dist) * force;
           const fy = (dy / dist) * force;

           forces.get(node1.id)!.fx += fx;
           forces.get(node1.id)!.fy += fy;
           forces.get(node2.id)!.fx -= fx;
           forces.get(node2.id)!.fy -= fy;
         }
       }

       // Attractive forces (connected nodes pull together)
       edges.forEach(edge => {
         const pos1 = positions.get(edge.source);
         const pos2 = positions.get(edge.target);
         if (!pos1 || !pos2) return;

         const dx = pos2.x - pos1.x;
         const dy = pos2.y - pos1.y;
         const dist = Math.sqrt(dx * dx + dy * dy + 0.01);

         const force = attractionStrength * dist;
         const fx = (dx / dist) * force;
         const fy = (dy / dist) * force;

         forces.get(edge.source)!.fx += fx;
         forces.get(edge.source)!.fy += fy;
         forces.get(edge.target)!.fx -= fx;
         forces.get(edge.target)!.fy -= fy;
       });

       // Apply forces with cooling
       const cooling = Math.pow(coolingFactor, iter);
       nodes.forEach(node => {
         const pos = positions.get(node.id)!;
         const force = forces.get(node.id)!;
         pos.x += force.fx * cooling;
         pos.y += force.fy * cooling;
       });
     }

     // Center the graph
     const avgX = Array.from(positions.values()).reduce((sum, pos) => sum + pos.x, 0) / positions.size;
     const avgY = Array.from(positions.values()).reduce((sum, pos) => sum + pos.y, 0) / positions.size;
     const offsetX = 500 - avgX;
     const offsetY = 300 - avgY;

     positions.forEach(pos => {
       pos.x += offsetX;
       pos.y += offsetY;
     });

     return positions;
   };
   ```

   **⚠️ DO NOT use circular layout:**

   ```typescript
   const y = Math.sin(angle) * radius + centerY;
   ```

## Technical Considerations

### Performance Optimization
- **Node Limit:** Default max_nodes=500 to prevent browser overload
- **Lazy Loading:** Load stats separately from main graph data
- **Debounced Search:** Add 300ms debounce to search input
- **Memoization:** Use React.memo for child components
- **Edge Filtering:** Only include edges between visible nodes

### LightRAG Integration
- **Graph Access:** Access via `rag._rag.chunk_entity_relation_graph` (NetworkXStorage wrapper, not direct NetworkX)
- **NetworkXStorage Methods:** Use `get_all_nodes()`, `get_all_edges()`, `get_all_labels()` instead of NetworkX methods
- **Read-Only:** No modifications to LightRAG's graph data
- **Graph Updates:** Graph automatically updates when documents are processed
- **Storage Format:** LightRAG stores graph as GraphML file in working directory
- **Data Structure:** Nodes and edges returned as list of dictionaries, not NetworkX tuples

### Error Handling
- **Empty Graph:** Show EmptyGraphState component
- **Missing RAG Engine:** Return 503 error with message
- **Invalid Filters:** Ignore invalid parameters, log warning
- **Network Errors:** Display error state with retry button

### Browser Compatibility
- **ReactFlow Support:** Modern browsers (Chrome, Firefox, Safari, Edge)
- **WebGL:** Not required (ReactFlow uses SVG/HTML)
- **Memory Usage:** Monitor with 500+ nodes, implement pagination if needed

### Security Considerations
- **No Authentication on Graph Endpoints:** Rely on existing session/auth middleware
- **Rate Limiting:** Consider adding rate limiting for heavy queries
- **Data Sanitization:** Escape HTML in node descriptions to prevent XSS
